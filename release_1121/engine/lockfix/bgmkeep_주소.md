# J/K 다시 시작 로드에서 음악 잇기 — 엔진 주소 조사

2026-11-24, 정적 분석만(게임을 띄우지 않음). 대상 `P:\AI\gclx-reltest\game\GUILTY CROWN LOST XMAS.exe`
(sha256 95e0c73f…82cd6, 1,381,376바이트, image base 0x400000).
표의 「확인」은 그 주소의 코드를 직접 읽은 것, 「추정」은 읽은 코드에서 미룬 것이다. 추정은 6절에 번호를 붙여 모았다.

## 0. 먼저 알아야 할 세 가지

1. **소리는 로드가 객체를 지우기 전에 이미 멈춘다.** 스트림 스레드(0x479d50)는 엔진 상태 `[0x620540]`의 윗자리가 0x1xx 가 아니면 스스로 끝낸다
   (검사 세 곳: 0x47a09f, 0x47a2b9, 0x47a566 → 끝내기 0x47a959: `[s+0x10c]=0`, `[s+0x108]=0`, 버퍼 Stop).
   대본의 `Load()` 내장(0x4126b0)이 0x412880 에서 상태를 **0x201** 로 바꾸는 순간부터 해당하므로, BGM 은 그 뒤 0.5초 안(버퍼 반쪽 알림 한 번)에 꺼진다.
   피어가 본 「로드 시작 1.3초 전에 스레드 쪽에서 멈춤(0x4793c0 을 안 거침)」이 이것이다.
   → 소멸할 때(0x455a00/0x479770) 떼어 두는 것만으로는 늦다. 그때 s 는 이미 스레드가 끝나고 버퍼가 멈춘 빈 껍데기다.
2. **s 를 살려 두는 것 자체는 쉽다.** 객체 소멸(0x455a00)은 `[s+0x104]==obj` 일 때만 스트림을 없앤다(0x455b52). 주인 포인터를 0 으로 바꾸면 객체만 사라지고 s(스레드·버퍼·파일 읽기)는 남는다.
   스트림 스레드·페이드 스레드는 주인 객체를 한 번도 읽지 않는다(소리 모듈 0x478300~0x47c700 과 ogg 디코더 껍데기 0x46cf00~0x46db90 에 `[reg+0x104]`·`[reg+0x1388]` 피연산자가 없음).
3. **객체째 살리는 길은 없다.** 로드는 뿌리 컨텍스트와 목록 머리를 통째로 0 으로 지우고(0x4437bf~0x44383b) 다시 만들며, 「이미 있는 객체를 목록에 끼우는」 함수가 따로 없다(끼우기는 할당과 한 몸: 0x44def0/0x44dff0).
   그래서 단위는 객체가 아니라 스트림 s 다 — 피어의 계획(옛 s 를 새 객체에 붙임)이 구조에 맞다.

권하는 길은 5절: 갈고리 4개(상태 검사 3 + 스트림 소멸 1)와 `Jump::restart()`·`Jump::load()` 안의 코드.

### 1-4. 깨우기 0x44baf0 (확인, 순회의 다음 노드 진행만 추정 7)

평목록(3-3)의 노드마다 `obj=[노드+0xc]`:
- `s=[obj+0x1388]`, `[s+0x3f4]`(효과)가 있으면 이름(`[s+0x3f4]+0x18`)에 따라 Chorus 0x47b960 / Echo 0x47baa0 / WavesReverb 0x47b860 / 그 밖 0x47c400 을 다시 건다 — **이 넷은 먼저 0x4793c0(정지)을 부른다.**
- 프로세스가 아니고(`[obj+0x1384]==0`) 상태가 0x11·0x13·0x14 이면 **`0x478c30(esi=s)`(재생)** → SetVolume(`[s+0x11c]×[s+0x118]`을 dB 로)·SetPan(`[s+0x120]`)·SetFrequency(`[s+0x124]`, 1000 이면 `[s+0x3cc]`) → 저장 상태가 0x13 이면 Sleep(16) 뒤 다시 멈춤(ResetEvent `[s+0x1a8]`, 상태 0x13).
- 영상(`[obj+0x138c]`), 프로세스(`[obj+0x1384]`: 0x473650 스레드를 0x48d380 으로 만듦).

0x478c30 은 로드 중(상태 0x202)이면 `[s+0x108]=0x11` 로 두고 `0x48d460(edi=[s+0x15c])`만 부른다. 0x48d460 은 스레드 기록의 `[rec+0xc]==2`(멈춘 채 만들어짐)일 때만 ResumeThread 하므로, **이미 돌고 있는 스레드에는 아무 일도 하지 않는다**(0x48d4b7).

### 2-3. 스트림 스레드가 s 밖에서 보는 것 (확인 — 피어의 빈칸)

- 전역: `[0x620540]` 상태(6곳), `[0x62056c]` 프로세스 종료 깃발(7곳), `[0x620014]`·`[0x620018]`·`[0x62001c]` 전체 음량, `[0x62057c]`·`[0x6205b0]` 음량 관련 깃발, `[0x620554]`(음성 끝 알림 이벤트), `[0x620570]`(멈춤 중 기다림). 기다림 도우미 0x484c00(3,-1,ms)는 `[0x620570]`·`[0x620548]`만 본다.
- 객체·M 잠금·B/E/C 이벤트·그리기 스레드는 건드리지 않는다. `[s+0x104]` 도 읽지 않는다.
- 끝내는 조건: ① `[0x62056c]!=0` ② `[s+0x108]==0` ③ 정지 알림(세 번째 이벤트) ④ **SILENT 가 아닌데 `([0x620540]&0xffffff00)!=0x100`** — 루프 머리 0x47a09f, 알림을 받고 깬 뒤 0x47a2b9, 멈춤에서 깬 뒤 0x47a566 ⑤ 반복 없는 곡이 끝에 닿음(0x47a5f4) ⑥ 상태 1(0x47a652).
  어느 쪽이든 0x47a959: 위치 0, 수준 0, 상태 0, 버퍼 Stop, 스레드 끝.
- 새로 만든 스레드는 처음에 상태가 0x202 인 동안 32ms 씩 기다리다가(0x479d8f~0x479dbd), 0x202 를 벗어나고 `[s+0x108]==0x11` 이면 버퍼 앞 반쪽을 채우고 **Play(0x47a05e, 돌아올 주소 0x47a060)**.
- `[0x62056c]` 를 1 로 쓰는 곳 16군데는 모두 종료·치명 오류 경로다(로드 실패 대화 상자 0x47293b 포함). 정상 로드에서는 안 켜진다.

## 3. 객체 (질문 3)

### 3-1. 필드 (확인, 문자열 셋의 뜻만 추정 1)

객체 블록은 0x18c0 바이트 할당, 앞 0x1478 을 0 으로.

|---|---|
| **+0x000** | **이름 char[0x100]** — `부모/자식` 꼴이면 마지막 조각만(0x44dda6~0x44ddcc) |
| +0x100 | 등록 함수의 둘째 인자 문자열(호출 기록+0x134 = 만들기 내장 이름으로 보임) |
| +0x200 | 저장본에서 되돌리는 문자열 |

「종류」 필드가 따로 있지는 않다. 소리 객체 = `[obj+0x1388]!=0`(그리고 `[s+0x104]==obj`), 소리의 갈래는 `[s+0x110]`.

### 3-2. 컨텍스트와 찾기 (확인)

- 컨텍스트 블록(뿌리는 고정 0x5aa7d0, 나머지는 힙): +4 주인 id(-1=없음), +8 뿌리 객체(0x1478), **+0x1464 = 뿌리의 첫 자식**(피어가 말한 0x5aa7d0+0x1464), +0x1480 다음 컨텍스트, +0x1484 앞 컨텍스트.
- `0x44de80`(ecx=ctxId) → 그 컨텍스트의 첫 객체. 스택 인자가 없어 `__fastcall(int)`처럼 부를 수 있다.
- `0x44e4a0` `obj* cdecl(obj* 첫 객체, const char* 경로)` — `a/b` 는 자식으로 내려가고, `@별칭` 은 0x462c80.
- `0x44dbb0` `obj* cdecl(ctxId, 이름)` — 같은 이름이 있으면 먼저 지우고(E 를 잡고 0x455890) 새로 만든다.

### 3-3. 평목록 (확인)

머리 구조체 둘: 0x5aa794(보통), 0x5aa7b0(상태 0x190). **첫 노드 = `[0x5aa7ac]` / `[0x5aa7c8]`**. 노드 0x480 바이트: +0 =1, **+0xc 객체**, +0x14 앞, +0x18 다음.
넣기 0x44e0f0 `cdecl(obj)`(객체를 만들 때 자동), 빼기 0x44e410(edx=obj, 두 목록을 다 뒤짐).
DLL 에서 객체를 훑을 때는 M 을 잡고(0x44abc0 / 0x44ac00 — `Jump::invalidate` 가 쓰는 꼴) 이 목록을 걷는 것이 가장 간단하다.

### 3-4. 떼기·끼우기

- 떼기만 하는 함수는 없다. 0x455890 이 떼고 곧바로 없앤다.
- 끼우기는 할당과 한 몸이다: 0x44def0(eax=형제, 끝에 새 객체), 0x44dff0(eax=부모, 첫 자식으로 새 객체). 이미 있는 객체를 다시 거는 함수는 없다.

## 5. 구상 (a)(b)(c) 평가와 권하는 길

### 5-1. 평가

- **(a) 지우기 대상에서 빼기** — 객체를 빼는 것은 안 된다(0절 3). **s 의 소멸만 건너뛰는 것**은 `[s+0x104]` 를 0 으로 바꾸는 한 줄로 된다. `[obj+0x1388]=0` 까지 할 필요는 없다(객체는 곧 사라진다). 주인을 0 으로 둔 동안 저장이 일어나면 그 소리가 저장본에서 빠지므로(1-3), 떼는 것은 origJumpLoad 안에서만.
- **(b) 같은 이름·같은 파일이면 옛 s 붙이기** — 길이 둘이다.
  - (b1) 0x478750 을 가로채 옛 s 를 돌려주기: **권하지 않는다.** 로더가 이어서 살아 있는 s 에 저장값을 덮어쓰고(특히 `[s+0x10c]` 위치, 0x46230f) 0x4795d0 을 부른다 → 0x47aed0 이 버퍼를 Stop 하고 스레드가 기다리는 알림 이벤트 셋을 닫아 버리며, 0x47a9a0 이 디코더를 저장 위치로 되돌리고 SetCurrentPosition(0) 한다. 재생이 끊기고 스레드가 닫힌 핸들을 기다리게 된다.
  - (b2) **엔진이 s2 를 평소대로 만들게 두고, origJumpLoad 가 돌아온 직후에 바꿔 끼우기: 권한다.** 그 시점은 주 스레드이고, s2 의 스레드는 아직 멈춘 채이며, 대본 스레드는 아직 안 깨어났다(0x4723ff 전). 뒤따르는 0x44baf0 은 옛 s 에 대해 「이미 도는 스레드 깨우기」(무동작)와 볼륨·팬·주파수 다시 걸기만 한다.
- **(c) 남은 것 치우기** — 짝을 못 찾은 옛 s 는 `((int(__cdecl*)(void**))*(void**)((char*)s+0x3f0))(&s)`.

### 5-2. 권하는 길

갈고리 넷(모두 native_hook_manifest 꼴로 가능, 원래 바이트는 부록 B):

| 자리 | 크기 | 하는 일 |
|---|---|---|
| 0x47a09f | 5 | `mov eax,[0x620540]` 대신: eax=상태, 단 **esi(s)가 지킬 목록에 있고 상태가 0x200~0x2ff 이면 0x100**. 0x47a0a4 로 돌아감 |
| 0x47a2b9 | 6 | 같은 일을 edx 에. 0x47a2bf 로 |
| 0x47a566 | 5 | 같은 일을 eax 에. 0x47a56b 로 |
| 0x479770 | 5 | 스트림 소멸: 다시 시작 로드 안(주 스레드, `Jump::loading`)이고 `*ps` 가 지킬 목록에 있으며 그 스레드가 살아 있으면(`WaitForSingleObject([s+0x15c],0)==WAIT_TIMEOUT`, `[s+0x108]==0x11`) → 주인 객체 이름을 적어 두고 `[s+0x104]=0; *ps=0; return 1`. 아니면 원래대로 |

세 상태 갈고리는 원래 명령 한 줄을 통째로 대신하고 다음 명령으로 곧장 뛰면 된다(트램펄린을 안 써도 됨).
지킬 것: ecx(종류), esi, edi, ebx 를 보존하고 **x87 을 쓰지 않는다** — 0x47a09f 에서는 FPU 스택에 값 셋이 올라가 있다. 플래그는 바로 뒤 `and` 가 덮으니 상관없다. 벌거숭이 스텁 안에서 작은 배열과 비교만 하는 것이 안전하다.

흐름:

1. **`Jump::restart()`**(대본 스레드, stage 가 성공한 뒤): M 을 잡고 평목록을 걸어 지킬 s 를 고른다 — `[s+0x104]==obj`, `[s+0x108]==0x11`, `[s+0x110]` 이 BGM(원하면 `[s+0x114]==-1` 인 SE 도), 효과 없음(`[s+0x3f4]==0`), 페이드 중 아님(`[s+0x334]==-1 || [s+0x31c]!=0`, 팬·주파수 블록도 같은 식). 목록에 넣는다. 이때부터 그 s 는 상태 0x201·0x202 에서도 스레드가 안 끝난다.
2. 대본이 `Load(-947002)` → 상태 0x201 → 목록 밖의 소리는 원래대로 꺼진다.
3. **origJumpLoad 안**: Delete("*") 가 객체를 지울 때 0x479770 갈고리가 지킬 s 를 떼어 둔다. 엔진은 저장본에서 obj2 + s2 를 만든다.
4. **`Jump::load()` 에서 origJumpLoad 가 돌아온 직후**: M 을 잡고 평목록에서 이름이 같은 소리 객체 obj2 를 찾아 5-3 의 조건을 본다. 맞으면 `[obj2+0x1388]=s; [s+0x104]=obj2;` 로 바꾸고 M 을 놓은 뒤 s2 를 없앤다. 안 맞거나 obj2 가 없으면 옛 s 를 없앤다(엔진 원래 동작으로 물러남).
5. 엔진 꼬리(Sleep(300), 0x44baf0, 상태 0x100)는 그대로 둔다. 목록은 다음 `restart()` 나 다음 체크포인트 캡처 때 비운다(상태가 0x100 으로 돌아오기 전에 비우면 안 된다 — 그것은 `Jump::load()` 가 돌아온 뒤다).

s2 없애기는 M 밖에서: 0x479770 이 s2 의 스레드를 깨워 끝나기를 500ms 까지 기다린다(깨어난 스레드는 로드 중 + 상태 0 을 보고 바로 끝난다, 0x479d9c~0x479dda).

### 5-3. 바꿔 끼울 때 맞춰야 하는 것

- 반드시 쓰는 두 칸: `[obj2+0x1388]=s`, `[s+0x104]=obj2`. 옛 s 의 `[s+0x10c]`(위치)는 건드리지 않는다.
- 같아야 지킬 수 있는 것(s2 = 체크포인트의 값, s = 지금 값): 파일 글(s+0 대 s2+0), 종류 `+0x110`, 상태 `+0x108`(둘 다 0x11), 반복 `+0x114`, 볼륨 `+0x11c`, 팬 `+0x120`, 주파수 `+0x124`, 깃발 `+0x140`, 그리고 s2 에 되살아난 페이드가 없을 것(`[s2+0x334]`, `[s2+0x370]`, `[s2+0x3ac]` 가 -1)·효과가 없을 것(`[s2+0x3f4]==0`).
  하나라도 다르면 체크포인트 이후에 대본이 그 소리를 바꾼 것이므로, 옛 s 를 버리고 s2 를 쓰는 편이 다시 시작의 뜻(체크포인트 상태로 돌아감)에 맞다.
- 0x44baf0 이 옛 s 에 하는 일: 효과가 있으면 다시 걸면서 **정지**시키므로(1-4) 효과 있는 소리는 처음부터 지키지 않는다. 그 밖에는 무동작 Resume + 같은 값의 SetVolume/SetPan/SetFrequency.

### 5-4. 위험과 한계

- **반복 지점 없는 곡이 0x201~0x202 사이에 끝에 닿는 경우**: 되감기 0x47a9a0 이 로드 가지를 타서 위치를 0 으로 안 돌린다(0x47a9b6). 상태가 0x100 으로 돌아올 때까지 그 곡만 짧게 비고, 돌아오면 처음부터 다시 이어진다. 막으려면 0x47a9b6(`cmp dword ptr [0x620540],0x202`, 10바이트)에도 같은 「지킬 s 면 로드 중이 아님」 스텁을 건다(여기서는 s 가 esi). 추정 9.
- 페이드 스레드 셋에도 같은 상태 검사가 있다. 페이드 중인 소리를 지키지 않으면 상관없다.
- 지키는 동안에도 옛 스레드는 0.5초마다 파일을 읽는다. 로드 경로에는 아카이브를 닫는 호출이 안 보이지만 끝까지 좇지는 않았다(추정 4).
- 잠금 고침(script_locks.inc)과는 자리가 겹치지 않는다(0x44c4c0, 0x473650, 0x449e50, 0x44c4ff). 공용 src 의 다른 조각도 소리 모듈 주소를 쓰지 않는다(grep 확인: 0x44c4c0 하나뿐).
- `PassageTime`/`RemainTime`(0x44c4c0 → `[obj+0x1388]` → 0x479500)은 바꿔 끼운 뒤 옛 s 를 읽으므로 가사 싱크는 실제 소리와 맞는다.
- 프로세스 컨텍스트에도 스트림 표가 있다(`[proc+0x70144+4k]` → `[x+0x64]`, 0x44c130~, 0x45e89d~). `[obj+0x1388]` 과 다른 길이고 여기 계획의 대상이 아니다(추정 3).

### 5-5. 물러날 길 (갈고리 없이)

끊김(1.5~2.75초)은 남기고 「되감김」만 없애는 길: `restart()` 에서 BGM 마다 `[s+0x10c]` 를 적어 두고(상태 0x201 이 되면 0 으로 지워지니 그 전에), origJumpLoad 가 돌아온 직후 같은 이름의 s2 에 `[s2+0x10c]=적어 둔 값` 을 넣고 `[s2+0x3e4](s2, [s2+0x128]+값)` 으로 찾아 둔다. s2 스레드는 아직 멈춘 채라 경합이 없다. 들리던 자리에 맞추려면 값에서 `[s+0x134]`~`[s+0x144]`(버퍼에 쌓여 있던 0.5~1초)를 뺀다.
